## 1. 專案目標

建立一套以「條件機率」為核心的台股分析與訊號系統，具備：

- 可解釋的訊號邏輯
- 可回測、可驗證的規則與模型
- 分階段擴充能力（短期 → 中期 → 長期）
- 明確的風險控管與失效條件

**核心定位：** AI 負責快速分析與訊號產生；人負責最終決策與風險承擔。

**非目標（初期不做）：**
- 全自動無人下單
- 保證獲利
- 高頻交易

## 2. 系統範圍

### 2.1 分析標的
- 大盤：加權指數（TAIEX）
- 權值觀察：台積電（2330）、台灣50（0050）、台達電（2308）
- 後續可擴充：電子、金融、個股池（Phase 3, T010）

### 2.2 訊號類型
- 方向訊號：偏多 / 偏空 / 中性
- 事件訊號：突破、跌破、量價異常、籌碼轉向
- 風險警示：急跌、波動放大、關鍵支撐失守
- **（v1.2 新增）** 11 大指標多空計分：x/11 符合數報告（§3.4）

### 2.3 時間框架
- 短線：1–5 個交易日
- 波段：1–4 週
- 中期：1–3 個月（後期擴充）

### 2.4 基本假設與範圍邊界
- 標的限現股，不含期貨、選擇權；融資融券資料（第二階段導入）僅作籌碼面參考指標，不用於產生槓桿部位建議
- 所有訊號皆須經人工確認才可能轉化為下單行為，系統本身不與下單介面連接
- 以個人／小規模自用為前提

### 3.4 第四階段：11 大指標多空訊號系統（signal.md）

**目標：** 建立基於「條件符合計數」的個股多空訊號預覽系統，以 x/11 格式顯示指標符合數並產出方向信號。

**核心概念：** 不使用權重，而是計算每個標的在多個指標中的符合數量，透過 Web 頁面以紅/綠/灰三個分明顯示是否符合。多頭指標使用紅色（符合）/灰色（不符合）；空頭指標使用綠色（符合）/灰色（不符合）。

**§3.4.1 多頭指標（11 項目）：**

分為四個子類別:

| # | 指標 | 類別 | 條件定義 |
|---|------|------|---------|
| 1 | 創 240 日新高 | 價量面 | 個股最近一次收盤價 ≥ 過去 240 天最高價 |
| 2 | 三大法人連續 3 日買超 | 籌碼面 | 三大法人過去 3 個交易日同步買超 |
| 3 | 外資買超 > 500 張 | 籌碼面 | 外資當日買超超過 500 張 |
| 4 | 外資連買 3 日 | 籌碼面 | 外資連續 3 個交易日買超 |
| 5 | 投信買超 > 500 張 | 籌碼面 | 投信當日買超超過 500 張 |
| 6 | 投信連買 3 日 | 籌碼面 | 投信連續 3 個交易日買超 |
| 7 | 主力連買 3 日 | 籌碼面 | 自營商連續 3 日買超（暫用自營商買賣超當代理） |
| 8 | 連 3 日收紅 K 棒 | 技術面 | 最近 3 個交易日皆收錄紅 K（收盤價 > 開市價） |
| 9 | 站上月線 | 技術面 | 現股價 > 月線 |
| 10 | 月營收成長 > 10% | 財務面 | 認知 = 上一月 vs 數學期月營收量，YoY > 10% |
| 11 | 月營收連續成長 | 財務面 | 連續兩個月 Mom（月環比）都有正成長 |

**§3.4.2 空頭指標（11 項目）：**

| # | 指標 | 類別 | 條件 |
|---|------|------|------|
| 1 | 創 240 日新低 | 價量面 | 收盤價 ≤ 過去 240 天最低價 |
| 2 | 三大法人連續 3 日賣超 | 籌碼面 | 三大法人最近 3 日同步賣超 |
| 3 | 外資賣超 > 500 張 | 籌碼面 | 外資當日賣超 > 500 張 |
| 4 | 外資連賣 3 日 | 籌碼面 | 外資連續 3 日賣超 |
| 5 | 投信賣超 > 500 張 | 籌碼面 | 投信當日賣超 > 500 張 |
| 6 | 投信連賣 3 日 | 籌碼面 | 投信連續 3 日賣超 |
| 7 | 主力連賣 3 日 | 籌碼面 | 自營商連續 3 日賣超（代理：主力） |
| 8 | 連 3 日收黑 K 棒 | 技術面 | 最近 3 日收錄黑 K（收盤 < 開盤） |
| 9 | 跌破月線 | 技術面 | 股價低於月 MA |
| 10 | 月營收負成長 > 10% | 財務面 | 月營收與去年同期相比減少 > 10% |
| 11 | 月營收連續負成長 | 財務面 | 連續兩個月月營收季比都為負值 |

**§3.4.3 資料源需求：**

| 資料項目 | 來源 | 更新頻率 | 備註 |
|---------|------|---------|------|
| 日 OHLCV | 既有 daily_prices 表 | 每日 | 由每日管線自動更新 |
| 三大法人買賣超 | 既有 institutional_flows 表 | 每日 | 外資/投信/自營商 |
| 月營收縮 | 既有 monthly_revenue 表 | 每月 | 由中 MOPS 系統 |
| 自營商日報 | 既有 institutional_flows 表的 dealer_net | 每日 | 代替「主力」 |

**§3.4.4 顯示規則：**

- 標題顯示 `x/11` 格式（符合數/總數）
- 符合條件 = 明顯文字（配合 §3.4.5 顏色）
- 不符合條件 = 灰色文字
- 多方標板：紅色文字表示符合
- 空方標板：綠色文字表示符合

**§3.4.5 技術實作指印刷：**

- 後端端點：`GET /api/signals/{stock_id}/scorecard` → 回傳多/空方各 11 項指標的 boolean 和 x/11 級數

**§3.4.6 驗收標杆：**

- [ ] 多空共 22 項指標全數有對應的計算邏輯與歷史日曆回測驗證
- [ ] 各標的輸出的 JSON API 包含 boolean 標記

## 4. 系統架構

```
[資料來源：TWSE／TPEx OpenAPI／MOPS 等（即時用法）]
        ↓
[資料擷取與清洗] ──→ [完整性檢查／異議宣告]
        ↓
[特徵定量] ──→ [技術指標 / 規則特徵 / 11大指標計算]
        ↓
[規則引擎／評分系統] ──→ [規則引擎(30條) / 健康燈檢查 / 11大指標計分]
        ↓
[訊號與風險評估] ──→ [基本規則訊號 / 四燈號 / 11指標 / 風險指標 / 久期框架]
        ↓
[輸出層] ──→ [Mkdown報告 / CSV / Telegram·Discord 通知 / API(儀表板)]
        ↓
[績效追蹤與回測] ──→ [規則回測 / 結構性變化控 / 11大指標歷史驗證]
```
