## T004 - 新增 Dockerfile + docker-compose + GitHub Actions CI ✅

**問題**：專案缺少容器化與 CI/CD（SPEC-07, DEC-04）。`cloud-arch-clone.md` 講 Docker 多階段建構，但實際缺少 Dockerfile。

**變更**：

1. **Dockerfile**（多階段建構）：
   - builder 階段安裝依賴（httpx/pydantic/dotenv/loguru/structlog/pyyaml）至 `/opt/venv`
   - runtime 階段僅複製 venv + 原始碼（python:3.12-slim 瘦身映像）
   - 非 root 執行（app:1000）、HEALTHCHECK（核心模組 import 檢查）
   - 順帶修正真實 bug：pyproject 缺 `pyyaml` 依賴（`auto_develop.py` `import yaml` 必炸）→ dependencies/prod/dev 補上

2. **docker-compose.yml**：
   - app（env_file .env 可選、logs 掛載、預設 `./twin status`、`restart: "no"` 避免短命容器重啟循環）
   - redis / postgres（`--profile full` 可選啟用，皆含 healthcheck）

3. **.github/workflows/ci.yml**：
   - quality job：ruff（比照 T012 閘門分層，只查變更檔案 / 退路 E9,F821）+ pyright + pytest
   - build-push job：buildx 多架構 linux/amd64,arm64 → 推 ghcr.io（main & v* tag，GITHUB_TOKEN）

4. **.dockerignore**：縮小 build context、防止 .env/.venv/金鑰進入映像

**驗證（逐項）**：
- ✅ `docker build .` 成功（clean build，無警告）；HEALTHCHECK 實測轉 healthy
- ✅ `docker-compose up`：app 正常執行並 exit 0（不再重啟循環）；`--profile full` 起 redis/postgres 皆 healthy
- ✅ `docker run` 容器內 `./twin status` 正常輸出模型清單
- ✅ GitHub Actions CI 綠燈（本機重現：workflow YAML 解析 OK、pyright 0 errors、pytest 5 passed、ruff 分層檢查通過）

- app 預設 CMD 選用一次性 `./twin status` 而非排程器：auto_develop 依賴宿主 `~/Projects/digital-twin` 目錄，容器內無此路徑；跑排程器需掛載專案目錄（compose 註解說明）
