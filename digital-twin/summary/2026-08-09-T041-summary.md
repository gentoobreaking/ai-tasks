# T041 任務完成摘要 — --model／Scheduler 預設不再硬編（2026-08-09）

## 背景問題
T039 之後 `.opencode/impl_providers.yaml` 已是備援鏈唯一事實來源，但 `main()`
的 `--model` argparse 預設仍是硬編 `"nvidia/nemotron-3-ultra-550b-a55b:free"`。
每次 CLI 執行都會把該值傳進 `call_model_for_implementation`，在 `_tier_model()`
openrouter 分支中**優先於 YAML**——YAML 換 openrouter 模型在 CLI 路徑下形同無效。

## 修正（依使用者建議改為「直接吃鏈」設計）
1. **Scheduler/CLI 不解析任何預設模型**：`AutoDevelopScheduler.__init__`
   `model: str | None = None`、`self.model = model` 直通；`call_model_for_implementation`
   收到 None 即完全依 YAML 鏈順位與各 tier model 決定
2. `main()` `--model` default 改 `None`（純 CLI 逃生覆蓋 openrouter tier）
3. `DEFAULT_IMPL_MODEL`（config.py）退位為**最後 fallback**：僅在無 YAML 或
   openrouter tier model 空缺時由 `_tier_model()` 使用
4. 移除原先「抽出 openrouter 預設」的弧形設計（單點概念與 YAML 全鏈精神不合）
