  private caPassword: string;

    this.isConnected = false;
    console.log("[MegaSecAdapter] 兆豐 API 已安全斷開連線。");
  }

      isConnected: this.isConnected,
      latencyMs: this.lastPingLatencyMs

<div class="callout callout-warning">
    <div class="callout-title">⚠️ 實體環境實證風控機制 (Production Risk Checklist)</div>
    當沖交易系統連線實體券商時，必須在 Adapter 層級強制導入以下三道實體防呆鎖：
</div>

<ol>
    <li><strong>重複委託攔截 (Idempotency Key Check)：</strong> 每個 <code>clientOrderId</code> 必須在記憶體 Map 中保留 30 分鐘，重複的送單指令將直接在 Adapter 端擋掉，防止因網路波動重複扣款下單。</li>
    <li><strong>強制 IOC / ROD 時間防爆鎖：</strong> 開盤 09:00:00 ~ 09:05:00 波動劇烈期，所有委託單強制限制為 <code>IOC (Immediate-or-Cancel)</code>，確保單子若沒有瞬間成交即刻失效，絕不留掛單在簿子上成為流動性被吃掉標的。</li>
    <li><strong>13:10 終極強制平倉熔斷 (Hard Flatten Circuit Breaker)：</strong> 時間一到 13:10:00，無論損益狀況，Adapter 自動阻擋任何開倉 (Open Position) 指令，並自動將所有在手持倉轉為「市價 / 平盤價」進行全數平倉，確保 100% 遵守現股當沖零留倉原則。</li>
</ol>

設計的重點在於：**「抽象化介面 (Interface Abstraction)」** 與 **「實體風控防呆 (Fail-Safe Architecture)」**。這樣無論底層對接的是兆豐證券、永豐 Shioaji 還是富邦證券，上層的當沖引擎與 Tactical Briefing 都不需要修改任何代碼。

### 一、 核心架構設計 (Adapter Pattern)

1. **`IBrokerAdapter` (標準介面):** 定義統一的下單 (`submitOrder`)、撤單 (`cancelOrder`)、查詢與成交回報訂閱。
2. **`MegaSecAdapter` (兆豐實作):** 封裝兆豐證券專屬 API 通訊協定、PKCS#7 經安電子簽章加解密、以及 Socket 心跳斷線重連機制。
3. **`ExecutionSafetyGuard` (下單風控防呆鎖):** 送出委託前最後一道防線，硬性檢查當沖權限、股數限制與 13:10 強制平倉點。

---

### 四、 實體環境必備三道風控鎖 (Production Fail-Safe)

1. **冪等性重複送單過濾 (Idempotency Key)：** 系統維護近 30 分鐘的 `clientOrderId` 快取，避免網路 Lag 導致重複下單。
2. **預設使用 IOC 委託：** 09:00~09:05 開盤劇烈期一律使用 `IOC` (Immediate-or-Cancel)，若無法立即成交即刻失效，防止掛單被掃。
3. **13:10 終極強制平倉 (Hard Flatten Breaker)：** 到達 13:10:00 時，Adapter 自動阻擋任何開倉，並自動調用平倉邏輯，確保 100% 達成當沖不留倉目標。
